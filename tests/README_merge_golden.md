# merge_clips golden regression harness

Proves that splitting `merge_clips.run()` into `build_plan()` + `render(plan)`
(v2.0.0 Reel Editor, Phase 1) is **pure code motion**.

---

## ⚠️ Capture must run at pre-refactor HEAD

Goldens captured *after* any edit to `backend/pipeline/merge_clips.py` describe
the new behavior, not the old one — the comparison then proves nothing. Capture
first, commit the fixtures, then refactor.

```bash
git status --short backend/pipeline/merge_clips.py   # must be empty before capturing
```

---

## Capture

Real FFmpeg, 15 cases, several minutes. Run from the repo root:

```bash
MERGE_GOLDEN=capture python -m pytest tests/test_merge_golden.py -m slow
```

Equivalent:

```bash
python -m pytest tests/test_merge_golden.py -m slow --update-golden
```

Writes `tests/fixtures/merge_golden/<case>.argv.json` and `<case>.meta.json`.
Commit both.

Re-capture a single case:

```bash
MERGE_GOLDEN=capture python -m pytest tests/test_merge_golden.py -m slow -k 07_audio_original
```

---

## Assert (default)

```bash
python -m pytest tests/test_merge_golden.py -m slow
```

Fails with the first differing argv index plus both argv lists.

Everything else in the suite skips the slow path:

```bash
python -m pytest -m "not slow"
```

---

## What is asserted

| Artifact | Assertion |
|---|---|
| `<case>.argv.json` | The ordered list of every `subprocess.run` argv, string-for-string |
| `<case>.meta.json` | The media row handed to `upsert_media()`, `metadata.merge` included |
| return value | `run()`'s result dict |

Byte identity of the output MP4 is **not** asserted — it varies across FFmpeg
and x264 builds, and the OOM retry path (`merge_clips.py:1528`) swaps
preset/threads mid-run, changing the bitstream legitimately.

### Determinism

`conftest_merge.merge_deterministic` pins everything that would otherwise drift:
seeded `random.shuffle`, `cleanup_segments=false`, stubbed
`get_track_for_pillar` / `_music_enter_offset`, and normalization of the
`mrg_<uuid>` merge id (`<MERGE_ID>`) and absolute repo paths (`<ROOT>`) in the
captured argv.

Test clips are generated by `tests/fixtures/clips/make_clips.py` from FFmpeg
`lavfi` sources — deterministic content matters because cv2 metrics from
`_window_metrics` feed the resolved filter strings.

---

## When a diff is legitimate

A failing assert means merge output changed. Either it's a bug, or you
deliberately changed rendering. For a deliberate change:

1. Read the diff and confirm every changed argv is one you intended.
2. Re-capture, review the fixture diff in the PR, and say in the commit message
   which cases moved and why.

Never re-capture to make red go green without reading the diff — that discards
the only regression signal this suite provides.

## Companion suite

`tests/test_merge_equivalence.py` — pure-function equivalence, no FFmpeg, runs
on every commit:

- `_fx_segment(i,d,cfg,met) == _fx_filter(_fx_decide(i,cfg,met), d)`
- `_segment_cleanup(...) == _cleanup_filters(_cleanup_decide(cfg,met))`
- `_resolve_joins()` reproduces the old inline `(variety, tdurs, tdur)`,
  including the `tdur >= min(final_durs)` clamp

These are `xfail(strict=False)` until the refactor lands, then flip to green on
their own. `test_legacy_joins_reference_is_self_consistent` is **not** xfail —
it guards the reference implementation against drift in `_VARIETY_TRANSITIONS`
and `_FPS` today.
